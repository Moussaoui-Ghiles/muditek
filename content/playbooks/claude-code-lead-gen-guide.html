1. Set Up the Project and Context Layer

A generic agent writes generic outreach. The thing that makes Claude Code run GTM like your team is the context you give it. The model is a commodity. The context you feed it is the moat. Build this first, before you wire a single tool.

The project folder

Make one folder for the work. Organize the subfolders the way you actually think about the job. One team keeps separate folders for ideas, tools being built, and agency management. For a lead-gen build, a folder called list-builder is enough to start.

Inside it, create the file the agent reads first on every run: CLAUDE.md. This is the brain. It holds your hard rules and points to everything else. Keep it short. It carries a plain business description and the rules the agent must follow.

The single most important thing to put in CLAUDE.md is proof, not adjectives. Closed deals carry more weight than descriptions. Put real examples of who bought from you and why in there. That is what the agent uses to recognize fit later. Do not write "we help fast-growing SaaS companies." Write who actually signed and what problem they had.

The five reference layers

Around the brain, feed the agent five layers of context:

  1. Brain. The root CLAUDE.md with hard rules that point to everything else.
  2. Strategy files. The written version of the calls you make in your head: your real ICP and the criteria you score on (company size, industry, funding, web traffic).
  3. Frameworks. The copy that has worked, the angles that book meetings, the sequence structure you trust:

Copy frameworks

# Copy frameworks

## First touch
- Open on the signal, not on us: the funding round, the new hire
- One specific observation about their business
- A single, low-friction ask

## What we never send
- "I hope this finds you well"
- A three-paragraph pitch before the ask
- Feature lists

## Proven openers (paste your real winners here)
- "Saw you just brought on a VP of Sales..."
- "Noticed [competitor tool] in your stack..."
  1. Benchmarks. The numbers that tell the agent what good looks like. This doubles as a quality gate: any list or draft that comes in under the bar gets reworked before it is sent.

Benchmarks

# Benchmarks

- Deliverable emails on a list: 90% or higher
- Reply rate on a real buying signal: 15 to 25%
- Win rate on qualified opportunities: around 28%
- A cold, signal-free list: around 91% get zero replies, average reply rate near 3.43%. That is the floor
  1. Examples. Real past outputs (lists and messages you personally signed off) in an examples folder. This locks format, tone, and structure, and stops the agent from drifting.

Build these in order: brain and ICP first, then copy frameworks, then benchmarks, then examples. Then keep stacking so it compounds. Every winning email goes back into frameworks. Every result sharpens the benchmarks.

Which context to keep: specific and current. Real ICP, winning copy, this quarter's benchmarks. Cut anything vague (things the model already knows) and anything stale. Outdated rules pull the agent wrong with confidence, so refresh on a schedule or cut them.

Never let the model guess

Most AI outbound reads like a robot wrote it because someone ran a good prompt on no data. The model fills the gap with something plausible, and the reply rate shows it a week later. So one rule runs on every prompt in this guide: never let the model guess. Before any research or writing step, paste the raw data in first. Their actual website copy, their LinkedIn profile, the jobs they have open. It is the least exciting step in the build, and it is the one most teams skip.

The .env file and the ICP file

Create a .env file in the folder and put your API keys inside it. The dot prefix keeps it out of casual shares and out of version control. Add a rule in CLAUDE.md: the agent reads a key only when it needs to make a call, and never prints a key back into chat.

Then have the agent turn your business into a written ICP. Ask it to write the ICP in its own words and save an icp.md file (title, industry, size band, geography, and so on). Read it once and fix anything off. Every later step leans on this file, so a wrong line here spreads everywhere.

Split the work into six roles

Do not try to run the whole motion from one prompt. People type "write cold emails to find clients," paste the output, and get no replies. You would never hire one person to be strategist, data researcher, copywriter, and LinkedIn manager at once. Split the work into six jobs, each with its own knowledge file (a skill is just a plain text file, like an onboarding doc for a new hire):

  1. Strategy. Who to go after. Scans your site, defines the ICP, scores every account out of 100. The judgment layer that decides which accounts get the motion's time.
  2. Signals. When to reach out. Watches triggers that mean "in market now": a funding round, a new CRO, an SDR hire, a competitor's tool in their stack.
  3. Data. Who to contact. Pulls verified contacts, but only on accounts that already cleared Strategy and Signals. Enrich late.
  4. Copy. What to say. Writes off the exact signal that fired.
  5. Execution. Running it. Sends emails, LinkedIn messages, and follow-ups in sequence across channels.
  6. System. Keeping it one motion. The orchestrator that connects the other five so one conversation runs end to end: signal fires, contact pulled, copy written off the signal, sequence sends, reply routes back.

Under the six roles sits a library of sub-skills grouped by job. A reference build runs an orchestrator on top plus 52 sub-skills in these categories: Clay (9 skills for automating work inside Clay), Signals (9 covering the most common signals and how to track each), Cold email, LinkedIn ads, LinkedIn content, List building, n8n automation, Email copywriting, Sales triggers, and SDR tool setup. Start with one skill, add the next once the first is pulling its weight, and keep stacking until the whole motion runs from one conversation.

Two layers plus governance

Wire these six as two layers. On top sit the master skills that route each request to the right specialist ("build a campaign" hands to Strategy, then Signals, then Data, in order). Underneath sit the reference files that hold what your company knows: ICP, scoring rules, tracked signals, templates. That reference layer is where your edge lives. The same six specialists with a different reference layer produce different results.

Keep the rules separate from the executing part so the agent cannot rewrite its own instructions mid-run. When it spots a change worth making, have it file a proposal you approve before it goes live. Change the system by editing one file: if your ICP shifts, edit the strategy file; a new signal, add a line to the signals file. The working primitives: rules that load based on what you are working on, skills that fire only when a task matches, subagents that each handle one job in their own context, and a memory file that carries learnings from session to session.

One client ran this file-based system for 10 months and produced 7.83M dollars in qualified pipeline and 1.52M dollars closed-won across 164 deals, with no new hires. The obvious alternative is hiring a GTM engineer. Postings for the role jumped 205 percent last year, and most of those hires become six-figure list-builders for the SDR team. A file does not ramp for a quarter, need a manager, or quit and take the playbook with it. It also forces the one number teams avoid: pipeline produced against cost to run, readable every day by campaign.

2. Audit and Collapse Your Tool Stack

Before you wire anything, cut what you do not need. Most GTM stacks are a pile of overlapping subscriptions billed per seat. Almost every one of those jobs is data an API can return per lookup.

Inventory every tool

One sheet, every GTM tool you pay for, four columns plus a last-used column. That last column surfaces most of the savings.

stack-audit.csv

# stack-audit.csv
tool,job,monthly_cost,seats,last_used
Apollo,find contacts,$99,3,this week
Prospeo,find emails,$49,1,this week
Hunter,find emails,$49,2,two months ago
Wiza,phone numbers,$83,1,this week
PredictLeads,buying signals,$120,1,last week
Trigify,social signals,$65,1,never

Group by job

Every stack reduces to about six GTM jobs. Group your tools under them:

  • Find company and contact: Apollo, Clay, big databases
  • Find the email: Prospeo, FullEnrich, Hunter
  • Find the phone: Wiza, Cognism, mobile finders
  • Read buying intent: PredictLeads, Common Room, Trigify
  • De-anonymize site visitors: RB2B, Vector
  • Send and sequence: Instantly, Lemlist, Smartlead

Decide keep, cut, or replace

  • Keep anything that does something no API returns: call-recording analysis, a proprietary dataset.
  • Cut anything last used more than 60 days ago. Cancel it the same day.
  • Replace anything whose whole job is data an API can return. That is every email, phone, and enrichment tool.

What a database actually sells

When you decide, remember a lead database sells three unbundled things:

  • The scrape. Mostly public LinkedIn data. You can do this yourself now.
  • The cleanup. Dedupe, verification, normalizing job titles. This becomes your step if you scrape.
  • The work email. LinkedIn and Google Maps do not publish it. This is the real thing databases have, so buy it per unit instead of per month.

Move the data jobs onto one API

Instead of a dozen tools, route your data jobs through one unified API that acts as a switchboard: one request, it picks the provider that can answer, falls through to the next on an empty result, and returns combined coverage. One key in, one invoice out, priced per credit rather than per seat, so a five-person team stops paying five subscriptions.

one call, one contact

# one call, one contact
POST api.gtm-stack.com/v1/contact
{ "name": "Dana Ruiz", "company": "Northwind" }

->  { "email": "dana@northwind.io", "phone": "+44...",
      "status": "verified", "source": "provider pool" }

Cancel old subs in the right order

  1. Export your data first. Access dies with the subscription, and some tools charge to return your records.
  2. Run the old tool and the new API side by side for a week. Compare three numbers: contacts found, data freshness, cost per lookup.
  3. Cancel only once the new setup matches or beats the old. Watch for annual lock-ins and buried cancel buttons.

The bill after

before -> after

# before  ->  after
12 tools, per seat        ~$1,400 / month
one GTM API, per lookup   ~$300 / month

Enriching 2,000 contacts a month costs tens of dollars in credits (a few cents per email, a bit more per phone) against a few hundred in seats. The marginal cost of a list drops far enough that list size and experiments stop being rationed.

3. Wire the Tools to the Agent

Now connect what you kept. The bottleneck that stalls most AI outbound is not the model's intelligence. It is tool access. Fix that here.

Prerequisites

  1. A coding agent that calls APIs and reads local files. Claude Code.
  2. An account and API key per tool you kept. The key lives under a settings tab named API or Developers. Most tools give free starter credits.
  3. A rough starting list of accounts or people. Rough is fine.

Keys in one .env

Put one key per tool in the .env file the agent reads on every run:

.env (one key per tool the agent can call)

# .env  (one key per tool the agent can call)
PROSPEO_API_KEY=xxxx
FULLENRICH_API_KEY=xxxx
WIZA_API_KEY=xxxx
PREDICTLEADS_API_KEY=xxxx
COMMONROOM_API_KEY=xxxx
INSTANTLY_API_KEY=xxxx

Every tool call follows the same shape: one request, one contact back.

one tool call, one contact

# one tool call, one contact
POST api.prospeo.io/email-finder
{ "first_name": "Dana", "last_name": "Ruiz", "company": "Northwind" }

->  { "email": "dana@northwind.io", "status": "verified" }

Two ways the agent talks to a tool

There are two connection styles. A plain REST call (the agent hits the endpoint directly using the key), or an MCP connection (the agent calls the tool in plain language through a bridge). MCP became the standard way tools expose themselves to agents in early 2026, and connecting a new tool went from a week of engineering to a sentence. To add an MCP connector: open connector settings in Claude, add a connector, point it at the tool's MCP. Whichever style you use, run one test lookup before any real work.

When you have a tool with dense docs, make the agent read them first. This is the difference between a skill that works and one that fails quietly:

Here is my [TOOL] API key: [KEY]. Research the [TOOL] API docs, build
a working understanding of the endpoints, and document them locally so
you do not re-fetch every time.

The routing table

For every job, tell the agent which tool to start with, which to fall back to, and how to break a tie. Keep it in a routing.md file the agent reads before every run. Each row is a job with three lines: first (start tool), then (fallback on empty), pick (the rule when choosing). A # marks a comment the agent ignores.

routing.md

# routing.md

## find the email
first   Prospeo        # verifies as it finds
then    FullEnrich     # cascades 20+ sources on a miss
pick    cheapest verified hit wins

## get the phone
first   Wiza           # turns a LinkedIn profile into contact data
then    FullEnrich
pick    quality first, phone data is worth more

## read intent
first   PredictLeads   # hiring, funding, tech adoption
then    Common Room    # product and community signals
pick    run both, keep the stronger read

## write the angle
first   your own skill # built from messages that have worked
pick    no fallback, this one is your voice

## send it
first   Instantly      # cold email and warmup
then    lemlist        # when a lead needs LinkedIn steps too
pick    match the channel to the lead tier

Add per-row extras only when a job earns the complexity: a verify line (a separate check before keeping a result) or a cap line (a credit limit for that one job).

The "write the angle" row points at your own skill: a short instruction file built from subject lines and openers that have worked. A first version:

skills/angles.md

# skills/angles.md
voice     plain and specific, one idea per sentence
open      with something true about their company
avoid     generic praise and "I came across your profile"
proof     we helped a similar team cut ramp time by 40%
close     a soft question, not a hard meeting ask

Cheap versus accurate rule. For bulk work (emails across a large list), price wins: a basic lookup at a few cents beats an aggregator checking 20 sources at three to four times the cost. For scarce or high-stakes work (a direct dial for a hot account), accuracy wins. Put a spend cap on the whole run either way. On an empty result after all fallbacks, mark that field not found, keep the rest of the row, and continue.

Score a tool before you add it

Rate any candidate 1 to 5. A score below 4 on the first three rows is a no.

CriterionPass bar
LatencyResponds in seconds, not minutes
Fails gracefullyClear error, not a timeout
Structured outputClean JSON the agent can parse
API / MCP accessDrivable without a dashboard click
Has a fallback pathA backup source or waterfall exists

Track each tool's latency separately from the model's, so a slow API does not read as a slow agent.

Data-layer definition of done: one input (a domain or a persona) returns a complete record, firmographics plus a verified contact, in a single call, with a fallback when it comes back empty. Test any data tool on 20 real domains. If it cannot return a complete record in one call for at least 17 of them, switch tools or add a waterfall.

Keep the stack lean

Each tool call is roughly 85 percent reliable, and many setups block and then error after about seven seconds. Chained calls compound: 4 calls chained is about 52 percent clean, 7 chained about 32 percent, 11 chained about 1 in 6. One good tool per layer beats the best tool per job, because fewer calls means more finished runs. Every dashboard-only tool that needs a human to click is a stall point and a first candidate for replacement.

Put a spend cap on everything

An unmetered agent once ran through 4,200 dollars in API credits before anyone noticed. Set a hard cap per run and a monthly account limit. The agent stops on either. Have it keep a running credit tally during a run and stop at the cap. This is not optional.

Rebuild recurring workflows as prompts

Once tools are wired, keep your repeat workflows as prompts in a file so they run identically each time:

Build a list of B2B SaaS founders in Berlin. Enrich each
one with a verified email and a phone number, and flag
anyone showing a recent hiring or funding signal.

Use the GTM API for every lookup, and skip anything that
comes back unverified.

A fuller one-prompt run, using the routing table:

Build a list of software CEOs in London. Find the ones
showing buying signals right now. Write three angles for
each, and load the result into my sequencer.

Use routing.md to pick the tool for every job. Verify each
email before you keep it, and cap the run at my budget.

Behind that prompt the agent builds the list, enriches (email row, then phone row), scores intent, writes angles from your own skill, and loads to the sequencer. It runs many contacts in parallel and retries a single slow or rate-limited call. A few hundred contacts finish in minutes.

Keep a run log to tune the tools

run-log.csv

# run-log.csv

Cost per finished contact runs around 15 to 20 cents on a run like this, so 1,000 ready contacts cost less than one monthly seat. The log surfaces tools that keep losing to their fallback (demote or drop them) and cheaper options beating pricier ones on quality (promote them).

4. The Full Architecture: 7 Layers, 19 APIs

Before you build each stage, here is the whole machine. Claude Code replaces the human integration layer, the person who copies data between tabs. It talks to each API directly and passes data from one layer to the next with no dashboard. Nineteen APIs map onto seven sequential layers, and each layer feeds the one below it.

Layer 1, Signal (catch intent before a form is filled).

  • PredictLeads. Hiring surges, funding rounds, tech adoption across 100M+ companies.
  • Common Room. Community, product, and GTM signals; warm leads from GitHub, Discord, LinkedIn, G2, and job changes.
  • Attention. Records every sales call, queried in plain language for competitor mentions and recurring objections.
  • RB2B and Vector. De-anonymize people already on your website, for example someone reading the pricing page.
  • When several signals fire at once, there is no clever rule. Use triggers that have actually closed for you before, and A/B test the uncertain ones.

Layer 2, Data (name and company into real contact data).

  • Openmart. 200M+ local business records; search by category and location, enrich to verified emails and phones.
  • Wiza. A single LinkedIn profile into verified contact data, 50+ data points on one person.
  • Prospeo. 98 percent-plus email accuracy on a 200M-record database; search by person, company, or domain.
  • FullEnrich. The waterfall play that saves the most money: one call cascades through 20+ providers until it lands email plus phone, at 80 percent-plus find rates. Replaced three separate enrichment subs for most teams.
  • Apollo. Underneath all of it for broad B2B firmographic and technographic list-building.

Layer 3, Action (Claude Code builds campaigns and fires sequences, no one in the UI).

  • Instantly. Programmatic cold email: campaigns, warmup, analytics, reply webhooks that fire the second a reply lands.
  • Lemlist. Multichannel sequences (email, LinkedIn, calls), routing each lead by its enrichment data.
  • LinkedIn Ads. Paid acquisition: create campaigns, sync audiences, retarget accounts showing intent.

Layer 4, Automation.

  • n8n. The glue that chains everything above, with triggers, branches, and loops that run on their own. A Layer 1 signal becomes a Layer 3 sent email overnight.

Layer 5, System of record.

  • Attio. AI-native CRM: people, companies, deals, custom objects, lists, tasks, real-time webhooks on every change. Everything points back to one record, because two tools disagreeing about an account is what breaks multi-play setups.

Layer 6, Conversion.

  • Cal.com. Embed booking links in emails, auto-route each meeting, sync every booking back to the CRM.

Layer 7, Revenue.

  • Hyperline. Billing, subscriptions, usage metering, invoicing, webhooks on every payment, and analytics on ARR, MRR, and churn.

You can also think of the core as four layers to build in order: Data (turn a name into a complete record), Signals (flag accounts with a live trigger), Orchestration (apply your rules and route), Execution (send, read replies, adjust). Concrete tools for a lean four-layer build:

  • Data. CompanyEnrich returns firmographics, contacts, and lookalikes from a 30M+ company base in a single call. Prospeo does free email and mobile lookup so the agent resolves contacts before you pay to scale. Apollo brings 275M+ contacts, reachable straight from Claude via its MCP server. LeadsFactory runs a LinkedIn waterfall that falls back to adjacent titles when the exact persona is not there, so the agent never lands on an empty list.
  • Signals. PredictLeads through its API, with Common Room, Sales Navigator, and BuiltWith as common companions.
  • Orchestration. Clay, whose Builder Agent spins up a workflow from one plain-English sentence and can fire external MCP actions after enrichment. Relevance AI is the programmable multi-agent layer with the governance to run in production, not just a demo.
  • Execution. Instantly manages inboxes and turns replies into meetings. Lemlist researches before the sequence so the first message carries context. Nooks works across phone, LinkedIn, and email and rewrites the sequence as call and reply outcomes come in.

Do not build the whole diagram at once. Start at your actual bottleneck, which is usually enrichment or the reply-to-CRM handoff. Wire that one seam clean, then add the next layer. Keep every layer simple enough to debug at 2am. Overbuilding branches and conditions is what kills these systems.

5. Source Your Leads

With context and tools in place, build lists. Three sourcing methods, from cheapest to most precise: scrape with Apify, search with Exa, or find closed-won lookalikes.

Method A: Scrape on demand with Apify

Apify is a marketplace of scrapers (LinkedIn search, LinkedIn profiles, Google Maps, Instagram, and more). Give it parameters, it returns structured data. The Apify MCP lets Claude Code operate it directly: read which scrapers exist, pick one, fill the parameters, run it, hand back the output. That removes the roughly 20 minutes of reading docs to choose among hundreds of scrapers.

Set up the account. Sign up and stay on the free tier, which gives 5 dollars of store credit. Spend the 5 dollars on a test run in your actual category, not a demo. Move to a paid plan only once a run produces a list you would actually send.

Give it your URL, not your targeting brief. Do not write out your ICP. Point the model at your own site and have it derive the ICP. In a real run, pointing it at the operator's own site and asking it to analyze the offer and work out the best 100 leads to contact, it pulled the offer, the service model, the ICP, the proof points, and the pricing off the page, then chose the targeting itself: founder, co-founder, or CEO, 11 to 200 employees, B2B software, US, verified emails only. It chose company size before job title, the opposite of how most people write an ICP.

Fix the emails. Scraped lists mix work and personal addresses. On that run, 70 of 100 were professional domains and 30 were personal. Convert the personal ones to work addresses through an email-finding API (LeadMagic, or a tool already in your stack). Tell Claude to read the API docs first so it stops guessing field names.

Build the list that has no export: your post engagers. Every post produces people who raised a hand. That is not a database segment you can buy. Pull everyone who engaged with your posts over the last week using the LinkedIn post reaction scraper (an Apify actor), rank the top ones against your ICP, push the survivors through Clay to qualify, and reach them on the channel they came from. One operator's post engagement counts ran 296, then 173, then 479, then 440.

The whole run, in order:

  1. Sign up for Apify, free tier, 5 dollars credit.
  2. Add the Apify MCP to Claude connectors. Once.
  3. Hand Claude your URL, not a brief.
  4. Read the ICP back. A wrong ICP is a website problem, so fix the site, not the list.
  5. Ask for the list. Let the model pick the scraper.
  6. Count the work domains.
  7. Convert the personal ones through an email API. Docs first.
  8. Pull your post engagers from the last week.
  9. Rank them against the ICP.
  10. Qualify in Clay before outreach.
  11. Send.

Steps 3 and 4 are the ones people skip. Keep the ICP the model produces and reuse it downstream. Rewriting it by hand causes targeting drift.

Costs. A 100-lead run is about 0.10 dollars of Apify compute on a 29 dollar per month plan, plus LeadMagic credits for the conversions, with Clay alongside for qualification. Apollo starts at 49 dollars a month before advanced filters. ZoomInfo does not publish a price at all, which tells you how that conversation goes. The marginal cost of a list drops to about 0.10 dollars, so list size stops being rationed.

Caveats. Scraped data is messier than database data, so the dedupe and verification step is on you now. Raw Google Maps output is especially noisy. Some community scrapers charge their own fee on top of Apify credits, so check an actor's pricing before scaling to thousands of rows. LinkedIn scrapers need your session cookies pasted into the actor settings, which takes about 30 seconds and the docs walk you through it.

Method B: A reusable list-builder with Exa

For a cleaner, repeatable project, use a search API built for list work. Exa is built for finding companies rather than general web search, and it is swappable. You need four things: Claude Code, a search API (Exa), an enrichment step, and the project folder from Chapter 1 that holds your context.

  1. Turn the business into an ICP. Have the agent write the ICP in its own words and save icp.md. Read it once, fix anything off.
  2. Build and score the list in one pass. Ask the agent to find companies and rank them at the same time. It checks each against the profile, gives a score of 0 to 10 with a short reason, and groups the output by industry and geography. Ask for 100 companies and usually a couple dozen land at 9 or higher. Those are your first calls of the week. Read a few reasons before trusting the scores. A shaky 9 usually means the ICP needs one more line of detail, so add it and re-run in a minute.
  3. Find the right contact. Ask the agent to find the person, starting with the top accounts so you can check quality first. It returns a clean row: name, title, company, domain, LinkedIn URL. Instruct it to leave a field blank when unsure. A guessed contact is worse than an empty cell. Happy with the first 10, point it at the rest.
  4. Enrich and hand off. The project calls the enrichment API for emails, drops the ones it cannot confirm, and writes a clean file ready for your sending tool.

The second list is one line away, because the ICP and keys are already in place. Point the agent at the folder, ask for more, and get another ranked list in about 10 minutes. What compounds is the judgment encoded in CLAUDE.md and the ICP, not the cheap, swappable search tool.

Method C: Closed-won lookalikes (highest precision)

Feed one company you already sold to, find companies that most resemble it, and lead the email with competitor proof. This is the accuracy play for high-ticket outreach.

Why Claude over lookalike tools like Ocean, PredictLeads, or Disco: those score similarity on firmographics and technographics only, so they cannot see the offer or positioning. Claude reads the closed-won company's actual site and offer, and scores others on offer match. Rule of thumb: database tools for volume plays (case-study amplification, TAM builds), Claude reading websites for accuracy plays (closed-won, high-ticket).

Stack: Instantly (send, enrichment, and verification in one), Claude Code (use the desktop app for your first campaigns so you get the visual UI and per-step approval), and a closed-won CSV exported from your CRM, one row per company, which must include the primary contact's job title. Open Claude Code in the Claude app's Code tab, and use Whisper Flow to talk instead of type so you are not writing the whole plan by hand.

The email is a fixed three-line framework where only the variables are editable:

  1. Acknowledgment: "I saw you offer {their_offer}."
  2. Proof: "We set up {what_you_did} for {their_competitor} and it generated {result}." This line is load-bearing. If it is not specific, kill the campaign.
  3. Resource ask: "Want the strategy we used?" Not "hop on a call."

Run eight prompts. Phase 1 runs once. Phases 2 through 5 run every campaign.

Phase 1, connect Instantly:

Prompt 1: "Here is my Instantly API key: [KEY]. Research the Instantly API docs, build a working understanding of the endpoints, and document them locally so you do not re-fetch every time."

Prompt 2: "Now build up the API calls for what we are planning to do: create a campaign, add a sequence, find emails, and push leads. List the calls you will use for each. Do not run anything yet, just show me the plan."

Phase 2, find lookalikes:

Prompt 3: "Here is my closed-won CSV. Tell me your understanding of the data before we do anything with it."

Prompt 4: "Find companies that look like [CLOSED-WON COMPANY]. Look at [your own tools directory or blog], G2, and other comparison sites on the web. For each candidate, analyze their positioning and their offer, not just their industry. Give each a similarity score from 1 to 10 so I can filter to the closest matches."

The "analyze positioning and offer, not just industry" line is non-negotiable. Without it, Claude returns adjacent-but-wrong matches. In a live run, that one line was the whole difference. Without it, Claude saw the closed-won company played in the outbound-tools space and handed back anything adjacent: Clay came back as a top match, a peer tool with a completely different offer. With the line in, the same run returned Smartlead, Woodpecker, Lemlist, Overloop, Reply, and Apollo. Every one a direct positioning-and-offer match, every one a company where "we work with your competitor" lands clean. Checkpoint: skim the top 5. If they are genuine competitors, the scoring worked. If not, re-run Prompt 4 with a tighter offer description.

Phase 3, find people. Target the same title you already closed.

Prompt 5: "For each company on the lookalike list, find the [VP of Sales / Head of Growth / your closed PC title]. Only include contacts based in [US, UK, EU]. Return name, company, title, and the offer each company runs."

Claude self-routes to a connected Clay connector if present, otherwise native web search, which is fine for a handful of specific people. Post-filter geography and seniority, since Sales Navigator itself admits 70 to 80 percent search accuracy.

Phase 4, copy:

Prompt 6: "Using this framework [paste the 3 lines above], write email one for the campaign. You may only edit the variables {their_offer}, {their_competitor}, {what_you_did}, and {result}. Keep the structure and the resource ask fixed. Pull {their_offer} from each company's site."

Phase 5, deploy and subject line:

Prompt 7: "Create a campaign in Instantly named 'Instantly Lookalike'. Add the copy above as email one. Find the work emails of these prospects using Instantly, then push them into the campaign once they are enriched. Leave the campaign in draft."

Prompt 8: "Give me 10 subject line variants for this campaign and set up an A/B split across the first send so we can let open rate pick the winner."

One judgment call on Prompt 8: Claude will usually propose "quick question" as a subject line. Do not ship it blind. The line is over-run, roughly half of ESPs treat it as a soft spam signal, and trained buyers filter it on sight. The counter-case is real too: Nick Abraham, who has run cold email agencies for years, still champions it with data behind him, so a generic subject does work in some ICPs. That is why Prompt 8 settles it with an A/B test instead of a guess.

Then eyeball the preview in Instantly and flip the campaign from draft to active. The eight prompts back to back take about 15 minutes on a 20 dollar per month Claude plan.

Three ways to extend this into a system: point Claude at your last 50 call transcripts in a vertical, catalog recurring pain, and when 12 of 15 say the same thing, that line becomes the next campaign's opener verbatim; seed a new lookalike campaign off every new case study (needs Ocean or PredictLeads for volume); surface objections from transcripts and pre-empt them in line one. The moat is closed-won data cleanly tracked, a copy framework tested for months, and the discipline to keep the send list narrow. Complicated campaigns almost never beat simple ones.

6. Run the Enrichment Waterfall

Whatever method sourced your list, you now have names and companies that need verified emails. Chain your email providers cheapest to priciest so the bulk gets found before premium rates hit. Think of the providers as stacked nets: the cheapest and widest at the top, the aggregator last. Coverage rises at each step while the bill stays small, because the cheap provider does most of the finding. Enrich late, only on accounts that already cleared fit and signal.

Prerequisites. An account and API key per provider, a list with at least a name and company (a LinkedIn link or website helps the match and lowers cost), and Claude Code. You can start with just two providers, one cheap and one aggregator.

Provider order and why:

  • LeadMagic first. Cheap, around 3 cents per email found, broad B2B, clears most of a list.
  • Prospeo second. Good at deriving the address from a company website domain.
  • Wiza third. LinkedIn-based, can pull a phone alongside the email, costs more.
  • FullEnrich last. The aggregator that checks 20+ sources in one call. Best odds and highest price, so it only sees the last stubborn names.

Build a waterfall/ folder with four things: the .env, the rules file, the input CSV, and an empty output/ folder.

.env

# .env

PROSPEO_API_KEY=xxxx
WIZA_API_KEY=xxxx
FULLENRICH_API_KEY=xxxx

waterfall.md

# waterfall.md

1. LeadMagic
2. Prospeo
3. Wiza
4. FullEnrich

## Rules
- For each person, try the sources in order.
- Stop at the first source that returns a valid, checked email.
- Check every email before keeping it. Drop the risky ones.
- Cap spend at 2,000 credits per run.
- Save one row per person: name, company, email, source, status.

contacts.csv

name,company,linkedin

The run prompt:

The agent handles rate-limit waits and retries, and keeps a running credit tally to stop at the cap.

Verification looks at three things: the address is syntactically correct, the company mail server exists, and the server accepts mail for this specific person. It drops catch-all addresses (where the server says yes to everyone) and anything risky or unknown. Statuses are verified, risky, or not found. Only send to verified. Bounces wreck your sender reputation, and Gmail and Outlook will route you to junk. Reputation takes weeks to build and one blast to dent.

A typical 100-contact result: LeadMagic finds 60, Prospeo adds 20 (80), Wiza adds 7 (87), FullEnrich adds 5 (92), with 8 unfindable, for 92 verified of 100.

The waterfall costs about 4 dollars per 100 contacts against roughly 10 dollars for a single premium provider, a 58 percent saving. Of the 8 unfound, some have a Wiza phone you can call or text, others you reach on LinkedIn, and re-running the same list in a month clears a couple more as jobs change.

the campaign in Instantly. Skip anything marked risky.

Tuning. Reorder providers per market: for LinkedIn-heavy prospects, move Wiza up; for tiny companies, lean on the domain-based finder. Tighten the cap while testing, loosen it for a real send. Add any provider that covers a gap. The rule never changes: cheapest and broadest first, most expensive last.

7. Score, Tier, and Match Effort to Account Worth

A verified list still needs to be ranked, because you cannot give every account the same effort. The key move is to split judgment from arithmetic. The model reads, researches, and writes. A Python script does every number that decides who gets contacted. Zero AI in the math. This fixes AI scoring drift, where the same account scores 8 on Monday and 6 on Thursday on identical data.

Build the list, then score it (three passes)

  1. Start with the segments most likely to convert. Three groups jump the queue: accounts already engaging with your brand (site visits or email opens), lookalikes of your five best current clients, and accounts throwing off live buying signals. Clay sits at the center, with Apollo, PredictLeads, and Common Room feeding the signal and firmographic data.
  2. Map the full addressable market around those segments. Filter by company size, geography, industry, revenue, and tech stack, and pull contacts through Clay, Wiza, and Prospeo. Deduplicate so no account lands in two campaigns at once, and enrich every lead with 8 to 12 real data points before anyone writes a word of copy.
  3. Score and sort. Grade each account against your five best customers and run that grading at volume, dropping every account in your TAM into one of three tiers.

Set up the scoring project

Put a CLAUDE.md at the center of the scoring folder:

CLAUDE.md

# CLAUDE.md

You run lead qualification for our company. Follow these rules on every run.

## Hard rules
- Never assign a score yourself. Run score.py and use its output.
- Read company_list.csv and scoring_criteria.md before scoring anything.
- Process the list in batches of 100 to 200 rows for quality.
- Default to plan mode. Show me the plan before you execute it.
- Exclude existing customers from any output.

## Where things live
- scoring_criteria.md   the rubric
- company_list.csv      the enriched data, one row per account
- score.py              the deterministic scoring
- templates/            the shape of every output
- .env                  API keys (Apollo, Instantly)

Turn enrichment into real numbers

Enrich each account into hard numbers before scoring: headcount, funding, revenue signals, tools in the stack, and monthly web traffic (a demand proxy). If a field cannot be a number or a hard fact, it belongs in the context the model reads, not in the scoring data. Score blanks as zero. No disclosed funding is a 0, never a flattering middle estimate. Enrich every lead with 8 to 12 real data points before any copy is written.

Write the rubric

Every rule points at a real column and hands back a fixed number. Include disqualifiers.

Scoring criteria

# Scoring criteria

## Disqualifiers (drop before scoring)
- Already a customer
- Fewer than 5 employees
- No work email found

## Headcount (employees)
- 200 or more ........ +30
- 50 to 199 .......... +20
- 10 to 49 ........... +10

## Funding raised (USD)
- 10M or more ........ +25
- 1M to 10M .......... +15

## Tech stack
- Runs a CRM we integrate with ........ +20

## Monthly web traffic
- 50,000 or more ..... +15
- 10,000 to 49,999 ... +8

## Tiers
- Tier 1: 70 and above
- Tier 2: 40 to 69
- Tier 3: below 40

Let Claude write the score.py from the rubric, then read the script once. That read is the cheapest insurance you will buy. Keep the script in version control next to the rubric. Score in batches of 100 to 200 rows. The script is exact at any size, but the model's surrounding work (context gathering, contact finding, copy) degrades when it juggles 10,000 rows at once.

If you prefer a weighted model, the same idea in one block, where Clay's AI grades and Claude Code runs it at volume:

Account scoring rubric. Clay AI grades, Claude Code runs it at volume.

# Account scoring rubric. Clay AI grades, Claude Code runs it at volume.
weights = {
    "firmographic_match": 40,   # size, industry, geography, revenue
    "tech_stack_match":   20,   # runs the tools your buyers run
    "buying_signal":      30,   # funding, hiring, tool change, site visit
    "brand_engagement":   10,   # opened an email, visited, follows you
}

score = weighted_score(account, weights)   # 0 to 100

if   score >= 75: tier = 1   # dream      -> manual, multichannel
elif score >= 45: tier = 2   # good       -> automated, value-first
else:             tier = 3   # plausible  -> email at scale

A worked account: 320 employees (+30), 14M raised (+25), HubSpot (+20), 60,000 visits (+15), not a customer with an email found, scores 90, Tier 1, high-touch. Against a 12-person company with no funding, no CRM, and 3,000 visits, which is +10, Tier 3, light nurture. One run of 100 companies returned 26 tier-one, 7 tier-two, and 67 excluded.

Match the effort to the tier

The tiers are not just labels. Each one gets a different motion.

Tier 1, by hand. Write the first 25 to 50 messages entirely by hand, no templates. This books meetings and produces the exact lines that become your templates. Run three channels at once: phone (via Nooks), LinkedIn (comment and conversation before any pitch), and email (only messages you would be happy to have read aloud in their leadership meeting). Warm the Tier 1 list with LinkedIn ads for weeks before you reach out.

Tier 2, automate but keep the value. Automated and multichannel, where every message is useful whether or not they reply. Lead with a resource matched to the signal: a hiring spike gets a teardown of that role's struggles, a funding round gets a benchmark, a new tool gets a read on what breaks next. Clay assembles the personalization and the resource, Lemlist runs email plus LinkedIn.

Tier 3, volume finds signal. The widest and cheapest tier, whose job is to collect information. Email at scale via Instantly with 4 to 5 copy variations in one campaign to learn which angle, subject, or offer pulls, in days. Winners travel up to Tier 2 and Tier 1.

Then route by tier automatically: Tier 1 is high-touch and human, Tier 2 is a warm automated sequence, Tier 3 is light nurture until signals change.

Failure modes to avoid: the model filling missing data instead of scoring it zero; a 20-rule rubric nobody can read; skipping the disqualifiers (which burns Tier 2 effort on companies you would never sign); and shipping the generated script unread (a wrong threshold can sit in production for months). The payoff is a system that is auditable (the rubric and script explain any score in about 10 seconds), reproducible, and holds at scale. A generic 10,000-email blast runs around a 0.5 percent response. Signal-based targeting off a scored list runs a 28 percent win rate on qualified opportunities.

Refresh your total addressable market at least quarterly, and aim to reach the entire addressable market every three to six months.

8. Run Cold Email Campaigns

Now build and send. The agent can produce an end-to-end campaign (list, copy, and live sequence) from a client folder. Five tools: Claude Code, optional voice input for faster prompts, an enrichment API (LeadMagic), a sending platform (Instantly, Lemlist, or Smartlead), and the client folder.

The client folder

Build it once per account and reuse it:

  ICP Context/        who to target, who to skip
  List Building/      the accounts you go after
  Context/            voice, positioning, offers
  Call Recordings/    discovery and sales call notes
  Onboarding Notes/   what you learned in week one
  Campaign Briefs/    briefs and event docs to send from

Fill it: discovery transcripts go in Call Recordings, how the client talks about itself goes in Context, who they sell to goes in ICP Context.

The five build steps

Step 1, target profile:

Open the client folder and read everything in ICP Context.
Write a short target profile: the titles worth reaching, the
industries in scope, the company size band, and the accounts
we should never contact. Save it back in ICP Context.

Aim for a target market of 10,000 to 50,000 companies. Smaller leaves no room to test, larger wastes spend.

Step 2, build the list:

Using the ICP and the account list in List Building, find
verified emails for people who match the in-scope titles.
Cap the enrichment at 2,000 credits. Remove anyone already
in a live campaign, then run the block list. Save the clean
list with every variable the copy will need.

A real run: pulled 105 verified prospects, removed 50 already in campaigns, dropped 9 on the block list, leaving 28 clean and ready to email.

Step 3, copy rules (a standing instruction):

You are a senior outbound operator.
Every email is 60 to 80 words.
Open with something useful to them, never with our credentials.
Do not ask for a meeting in the first email.
Mirror the prospect's language, not the client's.
Reference a real signal when one exists, and invent nothing.

The email anatomy: a give-first opener, 60 to 80 words, no meeting ask, one clear CTA.

Step 4, assemble:

  • Hard link CTA swapped for a soft question
  • Follow-ups added on day 4, day 9, day 16
  • Variables spot-checked and filled cleanly

The one-prompt version, once the folder is built:

Copy tied to a real trigger pulls up to 54.7 percent more replies than a generic template. Cross-channel sequences (email, LinkedIn, and ads together) lift response up to 287 percent over a single channel. Hold the deliverability rules below and cap follow-ups at four steps. The machinery is constant. The offer decides results, so spend saved time on the offer.

Deliverability is the non-negotiable floor

Get this wrong and nothing else matters, because your mail lands in spam.

  • Authenticate every domain with SPF, DKIM, and DMARC before you send.
  • Warm every new inbox for 2 to 3 weeks before it carries real volume.
  • Keep each inbox under 30 to 50 sends per day and rotate domains.
  • Run a spam check before shipping.

The DNS records, with DMARC starting at p=none to monitor and then moving to quarantine or reject:

A fully autonomous agent that hits a deliverability dip at 3am can torch a client's sending reputation, so set the fences (sending limits, a kill switch) before you let it run.

9. Handle Replies

Replies come back on their own schedule, so let the agent run a reply desk that reads, sorts, drafts in your voice, and routes, leaving only the warm ones for your approval. This takes about two minutes of your time a day.

You need four pieces: Claude Code as the operator, your sending platform's API (Instantly, Lemlist, and Smartlead expose the same), a CRM for follow-up tasks and notes, and a rules file with categories, voice, and examples.

Connect the inbox and run a read-only test first:

.env

# .env
INSTANTLY_API_KEY=xxxxxxxx-your-key-here-xxxxxxxx
Using the Instantly key in .env, pull every new reply from
the last 24 hours. Show me the sender, the campaign, and the
full text of each. Do not respond to anything yet.

Step 1, categories

reply-rules.md

# reply-rules.md

## Categories
- interested: says yes, asks a question, wants a call
- not now: good fit, names a later date
- referral: points to another person or team
- out of office: automatic away message
- unsubscribe: asks to be removed, or opts out
- unsure: does not clearly fit, hand to a human

## How to decide
- Read the whole reply, not just the first line.
- A polite brush-off is still a no, not a "not now."
- When two categories fit, pick the more cautious one.
- When you cannot tell, mark it unsure and stop.

The unsure bucket is the safety net. A wrong guess on a real prospect costs more than reading it yourself.

Step 2, responses, voice, and worked examples

Examples matter more than instructions, because the agent copies tone better than it follows rules.

## Responses
- interested: thank them, answer the question, propose two times.
- not now: agree, close the loop, set a note for the date they gave.
- referral: thank them, ask for a warm intro to the new name.
- out of office: send nothing, reschedule for the return date.

## Voice
- Keep it short and plain, no corporate filler.
- Never pushy. A question earns more than a hard ask.
- Match their tone. If they wrote two lines, write two lines.
- Never argue, never chase. Make it easy to say yes later.
## Examples
INTERESTED ->
  "Happy to. Does Tuesday 11 or Thursday 2 work? I'll send a
   short agenda so it's worth the 20 minutes."

NOT NOW ->
  "Totally fair. I'll close this out and send a quick note
   early next quarter. Anything you want me to include then?"

REFERRAL ->
  "Appreciate that. Mind a quick intro to Marco, or should I
   reach out and mention you pointed me his way?"

Step 3, the daily triage prompt

Run this each morning, and again in the late afternoon if volume is high:

Read every new reply from the last 24 hours. Sort each one
using reply-rules.md. Draft a response for the interested,
not-now, and referral replies, using the examples as a guide.
Set follow-ups where they belong. Leave the interested drafts
for me to approve, and flag anything you marked unsure.

Step 4, the routing prompt

For approved interested replies, send the draft and add the
booking link. For not-now replies, create a dated task in the
CRM with the date they named. For referrals, add the new
contact and start the intro sequence. For unsubscribes, add
them to the suppression list and confirm they are removed
from every active campaign.

Edge cases

## Edge cases
- "who is this / how did you get this": answer plainly, flag for me.
- angry or upset: send nothing, route to me.
- "we use a competitor": treat as interested, hand to me.
- "wrong person, try X": treat as a referral.

Wire reply speed for hot leads

For the strongest replies, do not wait for the morning triage. Route a positive reply to Slack and the rep's phone in real time:

Reply router (n8n or a small webhook).

# Reply router (n8n or a small webhook).
def on_inbound_reply(msg):
    intent = classify(msg.body)          # positive, neutral, negative
    if intent != "positive":
        return
    slack.post("#replies",
        f"{msg.sender} replied. Account: {msg.account} (Tier {msg.tier})")
    sms(account_owner(msg.account).phone,
        f"Hot reply from {msg.sender}. Call within the hour.")
    crm.create_task(msg.account, due="in 1 hour")

Three numbers to watch

  1. Positive reply rate. If it is low, fix targeting or offer upstream, not the desk.
  2. Time to first response. Push it toward minutes.
  3. Meetings booked from replies. This is the number that pays.

Each week, read the unsure pile and your manual re-sorts. Each one is a missing rule, so add it. In week one you correct categories and tone. By the end of week one most sorting is right and the drafts sound like you. By week two you are mostly approving, not editing. A new campaign or client carries over almost for free.

10. Build Signal-Based Outbound

Everything so far can run off a static list. This is the upgrade that produces the 28 percent win rate and 150K euro-plus ACVs. Instead of pulling a list on Monday, wire your sources so a buying signal becomes a personalized response with almost no human time in between. One rep saw a signal fire, sent a single 73-second Loom to one person, and closed a 200K euro-plus annual contract.

Four parts: detect, validate, respond, route.

Detect

Use continuous, always-on sources, not a weekly list pull. Common Room and Trigify for engagement and social signals, PredictLeads for hiring and tech-stack changes, RB2B to de-anonymize site visitors. Everything writes into one Clay table, where an account becomes a row with a live event feed. When a high-intent event fires, the account moves itself into a "work now" queue, ranked by what fired overnight.

Rank every signal by proximity to purchase, because your response scales with rank. A high-intent signal (a funding event, a pricing-page visit) earns an immediate personal human touch. A low-intent signal (a generic like) earns a light nudge or a watch tag. A signal is only high-intent if it maps to the specific thing you solve. Stack 2 to 3 correlated signals (a funding round plus three job posts for the exact function you serve) and a medium-intent event becomes high-intent. The triggers that mean "ready": a fresh funding round, hiring an SDR or a GTM role, a new CRO or VP of Sales, or a competitor's tool in their stack.

Validate against ICP

Run a fit check before any work: right segment, right size, right shape of problem. This kills inbound noise automatically. Encode your real ICP, size band, technographic fit, and hard-learned disqualifiers, and run it on every event before a human sees it. This protects human attention from proving a signal is junk.

Respond fast and personal

After validation, enrich to 8 to 12 data points, then have a person record the response. For the strongest signals, a short specific Loom. Speed matters, because a signal has a half-life. Loom anatomy: name the signal in the first 10 seconds, spend most of the time on the prospect's situation rather than your product, and end with a small specific ask, not "open to a chat?" Automate everything up to this point so the human has time to make this one touch genuinely good.

For the written version, the signal is the hook and the offer sits right behind it. Do not congratulate them on the raise.

Subject: {trigger} at {company}

Hi {first_name},

Saw {company} just {specific_trigger, e.g. "hired a VP of Sales"}.
Teams hitting that stage usually run into {specific_problem}.

We helped {similar_company} fix it by {one-line outcome}.
Worth a 15-min look at whether the same applies to you?

Route

Send the highest-intent signals straight to a rep for the personal response. Everything below goes to a nurture track, tagged and watched, orbiting until a stronger signal fires. Nothing is discarded and nothing weak gets full human effort. The routing logic:

IF icp_fit = high AND signal = funding/hiring/install
   then send now (priority queue)

IF icp_fit = high AND signal = none
   then nurture track (warm with content, recheck weekly)

IF icp_fit = borderline AND signal = strong
   then human review before send

IF icp_fit = low
   then drop (do not enrich further)

Cap sends at 30 to 50 per inbox per day with a hard credit ceiling per run. Every layer needs an answer to "what happens when this call fails?"

LayerFallback
DataReroute to backup source or waterfall
SignalsDrop into nurture, don't block the queue
OrchestrationSend to human review, not to send
ExecutionPause that inbox, rotate, keep the rest running

Add spend limits, approval gates (the agent proposes, a human commits anything customer-facing), and versioned rules.

The numbers behind this: around 91 percent of cold emails get zero replies, and the average reply rate sits near 3.43 percent. Writing off a real signal moves that to 15 to 25 percent, roughly a 5 to 7x lift, with elite teams clearing 30 percent. On the same 1,000 emails, a blast produces roughly 20 replies, 5 calls, and 1 deal, while a signal-driven approach produces 30 to 50 leads, 10-plus calls, and 3 deals. Intent-qualified accounts convert about 47 percent better and close about 43 percent bigger. Only about 25 percent of companies use intent tools, so this is still an edge.

Every acted-on signal plus its outcome teaches the system which triggers convert. A funding-plus-hiring combo that closed two deals gets weighted higher, and a content-like that never became pipeline gets demoted. Over months the queue becomes a model of your specific buyers.

11. Measure and Run the Weekly Loop

A system that works is not the same as a system that compounds. Run a weekly five-move loop: instrument, build, measure, kill, repeat.

Instrument before you build

Set up measurement before anything ships. Two pieces. Every lead should carry 8 to 12 data points before you write a word of copy. And the signals that matter (a funding round, a new VP, a competitor's tool in the stack, someone on your pricing page) each need a trigger wired into Common Room or Trigify so it reaches you on its own. Before the next campaign, write down the three numbers that would tell you it is working, and make sure something captures each one without you.

Build the system, not the campaign

Build the thing that produces, scores, and routes the list before anyone opens it. One engineer can sit under 80-plus client campaigns out of a single Clay workspace. Moving list-building off manual research onto a wired pipeline took one team from about 30 minutes to about 30 seconds per list. Take something you did three separate times last week, spend an afternoon turning it into a system, then stop doing it by hand.

Measure pipeline per dollar, ignore the rest

The wrong metrics are all activity: emails sent, lists built, enrichments run. The right metric is qualified pipeline per dollar spent on people and tooling, read daily, by campaign. That catches a sliding reply rate while you can still act.

Kill what is not clearing the bar

Cut up to 40 percent of the addressable market on purpose. One team barely cold calls anymore, because one booked meeting per 37 dials could not earn its place. Do not pull a play before it has had a fair run and enough volume, then decide on the numbers, not on how much work it was. In one example a broad-market campaign looked great on surface metrics, but the wired numbers showed thin replies on accounts with nothing going on. They shut it down and rebuilt around one intent signal. When that trigger fired on a Fortune-500 subsidiary, the system pulled it out of the automated flow and handed it to a person for a 73-second Loom, which became a 200K euro-plus annual contract.

Repeat and let it stack

Version what you built and run it again, so each pass starts higher. Six weeks later a play has been through a dozen revisions, handles more volume for less money per lead, and feeds data that sharpens targeting. Working and compounding are not the same thing.

Find your one distribution channel

The trap in 2026 is that AI inflates top-of-funnel metrics (impressions, likes), so every channel looks half-working and none gets cut. Roughly 54 percent of LinkedIn long-form posts are estimated AI-generated, about 48 percent of business social content is expected to be AI-produced by 2026 (up from 39 percent in 2024), and 87 percent of marketers used generative AI in at least one recurring workflow in Q1 2026, up from 51 percent a year earlier. Judge channels on bottom-of-funnel data the AI cannot inflate.

  • Define the fair test before betting. One channel, one owner, a fixed cadence, 90 days, written down. A content channel means a daily post. Cold email means defined small lists in the low hundreds with 8 to 12 enrichment points per lead, not a blast.
  • Build one scorecard that reads the bottom of the funnel. A single source of truth every channel writes into. Run it as a Clay table where every account is a row. The first channel to make contact stamps itself as first-touch, every later touch is appended to the same row, and outcome data joins from the CRM: meeting booked, pipeline created, closed-won. The four columns that matter are first-touch accounts, influenced deals, pipeline created in dollars, and cost to run (time plus spend over 90 days). Avoid last-touch attribution, because the last click is usually a booking link or branded search. Protect the first-touch field from downstream overwrites. The B2B benchmark: 100,000 impressions produces roughly 3 opportunities at the bottom, so judge on that number.
  • Refuse to diversify into noise. Once one channel works, the other nine drag on it. If one channel owns most first-touch accounts and the others sit within measurement noise, the data made the allocation call.
  • Set a kill line and a commit line on day one. 90 days with zero first-touch accounts reaching a real conversation means cut it without debate. A repeatable bottom-funnel signal, even a small one, means take it out of the experiment and commit fully.

Build the allbound loop on the winner

Once one channel wins, run content, ads, and outbound off one shared, scored account list so each channel feeds the others. All three read from the same file and write back to it, rather than keeping their own copies. Keep it in a spreadsheet or simple table with, at minimum, these columns: company, website domain, score, signals seen, current stage.

Scoring is rough on purpose: plus points for the right industry, size, and role, plus more for a fresh signal like new funding or a key hire, minus points for accounts gone quiet. Hot, warm, and cool tiers are enough to route treatment. The signals column records every noticed action (opened an email, visited the site, clicked an ad, announced a raise) and the score moves with it.

Each engine has one job. Content makes your name familiar before outreach, so a target account's engagement gets written back to the list. Ads cover the days you are not posting, and you build the audience from the scored list so you never pay to reach strangers. Outbound moves on a signal, not a calendar, so when a fitting account visits the pricing page, bursts ad clicks, raises funding, or hires a key role, it jumps to the top of the outreach queue.

The content itself comes off the same machine. Pick a content pillar and one idea, have the agent research it with a search tool like Exa or Linkup, and draft a post backed by real numbers. Call an infographic skill for the visual, add your own photo, and the post is near-ready. One optional last step: when someone replies to a campaign, add them on LinkedIn so they start seeing that content.

The compounding: content lowers ad cost (a warm audience clicks more and cheaper), ads lower outbound cost (a familiar name replies more), and outbound feeds the whole system (every reply and objection teaches which accounts and messages work). Cold email that lands on prospects who have seen the content three or four times gets measured 2 to 3 times the reply rate of cold-cold on the same copy. Layering LinkedIn content on top of cold email took one team from about 8,000 to 40,000 dollars a month.

Measure by account, not by channel. Group accounts by how many engines touched them (content-only, content plus ads, all three) and compare reply rate and win rate as coverage rises.

12. Keep the Right 20% Human

The machine runs the middle. You own the two ends. This is the 10-80-10 split.

  • The first 10 percent, you decide. Who to go after and why now, what a strong-fit account looks like, and the angle and offer you lead with.
  • The middle 80 percent, the machine. Research, enrichment, first drafts, follow-ups. This went cheap this year (it runs overnight for the cost of API calls) and is now table stakes, because your competitors have the same models.
  • The last 10 percent, you check. Read the output before any prospect does, and cut what is weak.

Never let an agent run a play start to finish. That last 20 percent is what clients pay for. One client paid 50,000 dollars a year for a data platform nobody logged into.

The numbers on each leg. On the front 10 percent, teams cut up to 40 percent of the addressable market on purpose and email fewer people who are ready to buy. Replacing cold dialing with a tiered signal score pulled 5 times the meetings off a smaller list. The list is the strategy. On the middle 80 percent, one team pushes 500,000-plus cold emails a month at peak with about 30 people, because the repetitive layer is fully software: Clay handles most structured work, and anything off the beaten path is scripted once and reused. On the back 10 percent, out of 500 overnight drafts you cut the roughly 12 that missed and send the 488 that landed. A content operation running a grader that scores every draft against a 50-point rubric, where anything under 38 goes back for a rewrite before a human touches it, pushed 581 posts in 87 days and drove 153K dollars in new MRR, with a human reading the last stretch.

Three artifacts you can build this week:

  1. A decision doc for the front 10 percent: who you are targeting and why now, what a good-fit account looks like, and the one angle. The brief the machine runs against.
  2. A foundation for the middle 80 percent: rules the agent cannot override, hard sending limits, and a kill switch for when deliverability slips.
  3. A review gate for the back 10 percent: decide before launch what gets checked and the bar it must clear (a score, a tone pass, a fact pass on anything personalized). Keep it cheap enough to run every batch.

Before you trust any AI SDR, run four tests

If you are tempted to buy an AI SDR instead of building this, know that every AI SDR is priced on activity (seats, sends, meetings booked), so the product optimizes the invoice line, not your revenue. AI-booked meeting to opportunity conversion runs about 15 percent, against 25 to 35 percent for an experienced human or hybrid team (Prospeo and DigitalApplied AI SDR benchmark reports). A tool can book double the meetings and leave less pipeline. AI meetings skew to smaller deals, they no-show more (outbound meetings already no-show around a third of the time, and a prospect who agreed to a link inside an automated thread with no real exchange pushes that higher), and conversion lags 30 to 45 days behind the meeting count, often landing in a different system owned by someone else, so by the time the number shows hollow the contract has renewed.

Run these four tests inside a 45-day paid pilot, not a demo. Write the pass line for each before you start, and let any test end the evaluation.

  1. Meeting-to-opportunity conversion. This decides the rest, so it goes first. Track every booked meeting and measure how many become qualified opportunities within 45 days. The metric is opportunities created, not meetings booked. Set the pass line against your own current number. Work the break-even before the pilot: a tool booking 300 meetings at 12 percent is 36 opportunities, and your team booking 120 at 30 percent is also 36, from a quarter of the activity with fewer no-shows. Make the vendor show conversion against that, and treat a refusal as the answer.
  2. Signal-triggered or ICP match. Ask what fires a sequence at a given account. If the answer is "they match the ICP filters you set," you are buying a faster spray. If it is a buying signal (a funding event, a relevant new hire, a tool added to the stack, a pricing-page visit), it is closer to real targeting. One team will not put a list into a sequence without at least one intent signal, pulled through Clay, PredictLeads, Common Room, and BuiltWith. During the pilot, tag which meetings came from a signal versus a plain match and compare their Test 1 conversion.
  3. Can a human own the handoff. The 60 seconds between "meeting requested" and "meeting confirmed" is the weakest part, where most no-shows are made. Ask whether the tool lets a human step in before the calendar invite goes out. The move is that a rep reads the triggering signal, scans the thread, and sends two sentences: what they saw, why they reached out, what they want to cover. It works as a sorting function, because no-shows ignore it and real ones come back with an agenda.
  4. Pipeline reported by source. If the dashboard sums meetings and stops, you cannot run the eval past month one. The practical bar: can the tool push meetings into HubSpot or Salesforce with enough structure that three months later you can ask which sequences and signals produced opportunities that closed? A tool hiding source-level pipeline does not want you running Test 1.

What AI does better than humans: list building, enrichment, signal detection, sequencing, follow-up timing, and deliverability throttling across domains. What it does not automate: the judgment layer, the 60 seconds before a meeting, the read on whether a buyer is real, and the offer built for a specific signal. Hybrid teams report 30 to 60 percent lower cost per meeting while holding conversion near human levels. The right split is to let AI own everything up to the moment a human read changes the outcome, put a person exactly there, and automate the 8 hours around it.

13. The 7-Day Build Plan and Troubleshooting

You do not need to build all of this at once. Wire the seam where your week actually goes first, usually enrichment or the reply-to-CRM handoff. A one-week runbook to stand up a working signal-led motion:

  • Day 1, map. List every tool the agent will touch and mark which it can drive via API or MCP versus which needs a human to click. Pick one tool per layer using the scorecard from Chapter 3.
  • Day 2, data. Test your enrichment on 20 real domains. You need at least 17 complete in one call, or add a waterfall.
  • Day 3, signals. Connect one signal source and filter to live triggers only.
  • Day 4, orchestration. Write three routing rules, set 30 to 50 sends per inbox per day, and set spend caps.
  • Day 5, execution. Connect the sender, load the signal-led template, and turn on reply classification.
  • Day 6, dry run. Run 20 accounts end to end and check every handoff by hand.
  • Day 7, review. Fix the seam where the data broke before you add any volume.

Definition of done (first pass):

  • One tool per layer, each drivable via API or MCP
  • A fallback on all four layers
  • Send and spend caps live in the orchestration layer
  • Reply classification routing interested leads
  • An approval gate on anything customer-facing
  • 20 accounts run clean, end to end

Common failures and their cause:

  • Runs die partway through. Too many chained calls. Cut to one tool per layer.
  • Replies read generic. Weak signals or data. Require a trigger before any send.
  • Credits drained overnight. No spend cap. Set hard limits in the orchestration layer.
  • Domains in spam. Over-sending. Hold 30 to 50 per inbox per day and keep new inboxes warming through their first 30 days.
  • The agent stalls silently. A slow API is hanging. Track per-tool latency, set timeouts, and add a fallback.

Start with the brain and the ICP, wire your one worst bottleneck, prove it on 20 accounts, then add the next layer. The offer decides the results. The system just makes sure the offer reaches the right person at the right moment, at a marginal cost close to zero.
