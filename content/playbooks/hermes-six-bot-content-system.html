How to Build a Six-Bot Content System With Hermes

Turn one relevant topic into verified research, one clear angle, a useful main piece, and platform-specific content without losing the sources or your judgment.

Six Hermes bots each own one part of the job. Obsidian holds the shared knowledge. Hermes Kanban moves one campaign record through the workflow. You approve what gets published and what the system learns.

1. Understand the architecture

Six separate chats do not make a content system.

The system works because each bot receives a defined input, makes one decision, and returns a defined handoff.

If research never reaches the strategist, the angle becomes generic. If the writer never receives the source package, claims drift. If distribution only shortens the finished article, every platform gets the same post in a different size. If performance never updates the playbooks, the system repeats the same mistakes.

Hermes botsEach bot makes one editorial decision and hands the result to the next bot.
ObsidianStores the approved voice, audience, offer, proof, platform, and performance notes.
Hermes KanbanTracks assignments, dependencies, comments, revisions, and approvals between profiles.

Use chat for questions. Keep campaign data and task status in files and Kanban.

LayerWhat it controlsWhat it must not replace
Bot ModeThe visible roster and communication between named bots.The durable campaign record.
ProfilesSeparate memory, sessions, skills, and instructions for each role.The shared editorial knowledge.
ObsidianThe accepted knowledge every role is allowed to read.Draft storage for every thought the bots produce.
KanbanDependencies, handoffs, comments, review, retries, and human input.The editorial decisions owned by the bots and you.

2. Build the shared content brain

Start with the knowledge all six roles need to make compatible decisions.

Use plain Markdown files inside one Obsidian vault. Keep accepted rules, reusable examples, evidence standards, and links to source material. Keep working drafts inside campaign folders so discarded work does not pollute long-term memory.

The index.md file is the entry point every bot reads first. It defines what you publish, who it is for, what every campaign must contain, how work moves, and which decisions require you.

Minimum index.md

# What we publish about
- Applied AI systems for operators
- Practical agent builds
- New tools with a specific business use

# Who we publish for
- Founders
- Marketers
- AI operators

# Every campaign must contain
- One clear reader outcome
- One central claim
- Direct evidence for important claims
- One reusable framework, workflow, or decision rule
- Platform-native distribution

# Routing
- New signals → Signal Scout
- Approved signals → Researcher
- Complete source packages → Content Strategist
- Approved angle briefs → Long-Form Writer
- Approved main pieces → Distribution Bot
- Every external asset → Editor

# Human approval
- Required before publishing
- Required before changing voice, audience, offer, or evidence rules
- Required before a performance lesson becomes a permanent rule

3. Give every bot a fixed contract

"Make great content" gives every bot the same vague job.

Give each profile one decision, a fixed set of inputs, one exact output, a clear stopping point, and checks that show when the work is done.

OwnsThe decision this bot makes.
ReadsThe files and fields it may use.
ReturnsThe artifact the next bot receives.
Must notDecisions reserved for another bot or a person.
Done whenThe checks that complete the handoff.

Profile contract skeleton

ROLE: [role name]

OWNS
[one editorial decision]

READS
[approved vault files and campaign fields]

RETURNS
[one defined handoff artifact]

MUST NOT
[decisions owned by another role or a human]

DONE WHEN
[checks that prove the handoff is complete]

If a required input is missing, return the task to the previous stage.
Do not fill the gap with a plausible assumption.

4. Configure the six bots

Give each bot one decision.

1

Signal Scout

Owns: whether a topic deserves research now.

Reads: launches, research, customer questions, objections, clips from credible sources, and active conversations.

Returns: signal brief or rejection.

2

Researcher

Owns: what the available evidence supports.

Reads: the approved signal and original sources.

Returns: evidence package with direct sources.

3

Content Strategist

Owns: the reader, outcome, tension, thesis, format, and reusable object.

Reads: the signal, evidence package, audience, offer, and platform rules.

Returns: one angle brief.

4

Long-Form Writer

Owns: the deepest useful version of the approved angle.

Reads: the angle brief, evidence package, voice rules, and relevant content patterns.

Returns: the main piece.

5

Distribution Bot

Owns: the platform-specific entry point for each asset.

Reads: the original angle, main piece, and platform playbooks.

Returns: distinct X, LinkedIn, newsletter, carousel, and video assets.

6

Editor

Owns: whether the complete campaign is ready for your review.

Reads: every asset together, the source package, voice rules, and campaign objective.

Returns: approval, revision request, or rejection.

Signal Scout handoff

  • What happened.
  • Why the audience may care.
  • The original source and strongest clip, screenshot, chart, or result.
  • The question the finished piece could answer.
  • How quickly the opportunity may decay.
  • A short rejection reason when the signal is weak.

Signal Scout should reject far more ideas than it approves. It does not choose the thesis or draft the post.

Researcher handoff

  • The current event or source creating urgency.
  • Three to seven verified claims.
  • Direct URLs for every important claim.
  • Relevant quotations or timestamped clips.
  • Contradictions, missing evidence, and what the sources do not prove.
  • Two or three mechanisms worth explaining.

The Researcher verifies the original claim, checks primary sources, records useful numbers, and separates facts from inference. It does not choose a headline first and hunt for supporting evidence.

The reusable object is the template, framework, visual, or checklist the reader can keep. The Content Strategist returns one recommendation and explains why the rejected directions are weaker.

Main piece checklist

  • An outcome-led headline.
  • A first screen that makes the result tangible.
  • Visible architecture.
  • Claims tied to the source package.
  • A complete workflow or framework.
  • Examples where a reader could get stuck.
  • A short ending that makes the idea easy to remember.

The Long-Form Writer creates the source material for the campaign. It does not write every platform asset.

Editor checks

  • Several hooks making the same claim.
  • The same opening story repeated across platforms.
  • Unsupported claims introduced during distribution.
  • Tone changes between assets.
  • A carousel that adds nothing beyond the main piece.
  • A call to action that does not match the reader.
  • One platform receiving much less value than the others.

The Editor can approve, request a revision, or reject an asset. It cannot publish.

Your review screen should show the final copy, supporting source, intended platform, media, and the decision you need to make.

6. Build the team in Hermes

Profiles hold role memory. Bot Mode makes the team visible. Kanban carries the work.

  1. Open the current Hermes desktop application.
  2. Create one isolated profile for each of the six roles.
  3. Clone the same base configuration so the profiles share the model and core capabilities while keeping separate sessions and memory.
  4. Put the role contract inside each profile's SOUL file.
  5. Point each profile at the same media-company vault.
  6. Restrict each role to the files and campaign fields it is expected to change.
  7. Add the six profiles to one Bot Mode roster.
  8. Keep one persistent room for questions and interventions.
  9. Create one Kanban board and start its dispatcher.
  10. Assign the first campaign to Signal Scout.

Hermes Kanban keeps the task and handoff state on a durable SQLite-backed board. Tasks can wait for dependencies, carry comments, survive restarts, enter review, and return to the correct profile when changes are required.

7. Run the first campaign

Use the system itself as the first assignment.

First Signal Scout prompt

Find the strongest practical content opportunity created by the latest
Hermes Bot Mode release.

Prioritize a specific workflow a solo operator can build now.

Return:
- the official source
- current audience interest
- useful authority clips
- the question the finished piece should answer
- reasons to reject weak angles

Do not draft content.

The expected route is:

  1. Signal Scout identifies Bot Mode as the event and the six-bot content operation as the possible workflow.
  2. Researcher checks the official release, documentation, walkthroughs, and community tests. It records what Bot Mode, Profiles, and Kanban actually do.
  3. Content Strategist chooses the reader, outcome, tension, thesis, format, and reusable object.
  4. Long-Form Writer creates the complete guide from the approved angle and evidence.
  5. Distribution Bot develops different entry points based on the capability, architecture, research, implementation, and results.
  6. Editor compares the full package, checks every important claim against the source package, and prepares it for your review.
one campaign → one record → six decisions → one human approval queue

8. Rebuild the idea for each platform

Distribution is not shortening one article five times.

The Distribution Bot returns to the angle brief. It chooses the part of the argument that fits what people expect on each platform.

PlatformUseful entry point
XThe sharpest claim, proof point, build sequence, or authority clip.
LinkedInThe operator lesson, internal decision, or before-and-after workflow.
CarouselThe framework that becomes easier to understand when shown visually.
VideoA spoken narrative built around tension, demonstration, and result.
NewsletterThe nuance, examples, and personal context that would overload a short post.

Every asset needs its own reason to exist, even for someone who already saw another part of the campaign.

A seven-day X sequence

DAY 1Main argument and complete guide
DAY 2Architecture: bots, brain, production desk
DAY 3Authority clip and one mechanism
DAY 4Practical build or handoff contract
DAY 5Why one chat repeats itself
DAY 6How the feedback loop works
DAY 7The complete system in one visual

9. Keep approval human

The first version prepares everything and publishes nothing.

You approve:

  • The central angle.
  • The main draft.
  • Claims about products, people, or results.
  • Every public post.
  • Changes to voice, audience, offer, or editorial policy.
  • Performance lessons that become permanent rules.

Every approval, revision, and rejection becomes an example the bots can follow. When you keep making the same correction, add it to the relevant playbook. Keep publishing approval human until the review queue stops surfacing serious errors.

Automate the repeated decisions. Keep your judgment in the publishing process.

10. Close the learning loop

Reporting numbers is not learning. The next campaign must change.

After every campaign, record:

  • The signal and subject.
  • The reader outcome and central angle.
  • The hook type, format, and platform.
  • Impressions or reach.
  • Meaningful engagement.
  • Clicks, follows, replies, or conversions tied to the goal.
  • What the Editor approved or revised.
  • What should be tested again.

You do not need a seventh permanent bot. Give the Editor one weekly review task. It compares recent campaigns and proposes changes to hooks, angles, and platform rules. Every proposal must name the posts supporting it.

KEEP

Patterns that worked repeatedly and still match the strategy.

TEST

Promising patterns that need another controlled attempt.

STOP

Repeatedly weak patterns, duplicated formats, or expensive work with no useful result.

One strong result creates a hypothesis, not a permanent rule. You approve each change before the shared brain updates.

11. Build the smallest useful version

Do not begin with six fully autonomous bots.

  1. Create the Obsidian content brain and fill the minimum voice, audience, proof, and platform files.
  2. Create Signal Scout, Researcher, and Editor first.
  3. Run three real ideas through signal, research, and review.
  4. Add Content Strategist when the evidence packages are consistently useful.
  5. Add Long-Form Writer when the angle briefs constrain the draft clearly.
  6. Add Distribution Bot after one main format is working.
  7. Record performance and review proposed playbook changes once a week.
  8. Keep approval human while the system learns your standards.

The first useful version can return one researched opportunity, one angle brief, and one approval-ready post. Add the main piece next. Then add the platform package. Then close the performance loop.

Hermes runs the team. Obsidian holds the shared knowledge. Your approvals decide what the system learns.
