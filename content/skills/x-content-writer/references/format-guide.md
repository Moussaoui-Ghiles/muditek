# X format guide

Choose the smallest format that carries the complete idea.

## Short post

Use for one defensible point, one reaction, or one visual.

Shape:

```text
[specific true line]
[optional consequence or clarification]
```

The first line carries the complete bet. If the point needs proof or a second argument, use a long post.

## Long post

Use for one complete explanation, procedure, argument, case, or framework.

Shape:

```text
[hook that names the subject and promise]
[context or tension]
[body in the source's real structure]
[supported conclusion]
```

Use short paragraphs and real section cues. One post should hold the value without requiring a reply chain.

## Thread

Use only when each ordered unit needs its own space, such as a multi-step procedure, chaptered guide, or prompt pack.

Shape:

```text
Post 1: complete hook, promise, and enough value to stand alone
Posts 2-N: one ordered unit per post
Final post: supported recap and approved next step
```

Do not split a normal essay into fragments. Do not use tweet counters unless the user requests them.

## Article

Use for a deep evergreen reference that needs sections, examples, and citations. Pair it with a separate launch post if distribution is part of the task.

## Asset post

Use only when the resource exists.

State:

- what the asset is;
- the real contents;
- the problem it solves;
- who it is for;
- how to access it.

Do not advertise a file that has no usable link. Do not use a comment or DM gate unless the user explicitly requests one.

## Media

Use media when it provides evidence or carries information: a real screenshot, diagram, chart, demo, or asset preview. Decorative media does not repair a weak post.
